# SDT 内容成稿

先诊断选题的形式、表达效率、认知落差和产品关系，再直接承担实际生产。

## 前置门

完整流程使用 sdt-topic 选题卡和 sdt-account 账号档案。单独调用时，只要用户给出已确认选题即可开始；涉及第一人称经历或产品时，再补齐相应事实。

## 四项诊断

1. 形式：观点冲突优先口播，清单教程优先图文，长逻辑优先长视频或文章，案例数据可图文与视频组合。
2. 表达：能否用一句话说清核心，是否把多数篇幅浪费在包装。
3. 落差：受众看完会得到什么新解释，而不只是熟悉结论。
4. 产品：内容是否先独立成立，产品是否参与真实场景而非最后硬插。

## 工作流

1. 选择最能承载机制的形式：口播、剧情、探店、访谈、教程图文或观点图文。
2. 写一句核心命题，整条内容只服务这一件事。
3. 设计结构：公共张力 → 具体证明 → 认知推进 → 目标账号场景 → 克制落点。
4. 把来源事实、账号事实和创作推断分开。
5. 生成完整正文或逐字稿；保持目标账号稳定语气。
6. 结尾先完成观点，再自然出现产品或空间。不得把产品写成万能解决方案。
7. 输出需要拍摄的画面、道具、场景和不可缺失事实。

## 口播要求

- 开头阶段只放占位句，正式优化交给 sdt-hook。
- 每段承担一个功能，口语句优先。
- 不编造第一人称经历、客户反馈、营业数据或疗效。
- 不用未经证实的精确数字制造冲击。
- 跨域迁移要重写论证和场景，不能沿用原内容句法骨架。

## 交付

使用 assets/content-package.md，包含核心命题、内容形式、目标时长、结构、成稿、镜头提示、产品落点、事实核验清单和下一步包装输入。
