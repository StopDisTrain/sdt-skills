# SDT：内容生产系统

把账号事实、公开内容证据和 SDT 自有方法组合成可追溯的内容工具箱。每个 sdt-* 都是独立 Skill；总入口只负责识别当前任务和组织必要衔接。

## 默认行为：单步骤优先

1. 读取当前对话，识别用户此刻要的一个交付。
2. 能直接确定模块时，只执行该模块，不要求补做上游全流程。
3. 只索取完成本步骤不可缺少的信息；不要为了“流程完整”索取无关材料。
4. 用户说“只要标题”“只检查开头”“只帮我找选题”时，在对应结果交付后停止。
5. 只有用户明确说“完整生产、从头到尾、整套做完”时，才进入完整生产线。

读 references/module-map.md 选择模块。

## 核心规则

1. 需要第一人称代写或账号适配时先确认账号事实；纯标题公式、通用质检等单项任务不强制建完整档案。
2. 先保留来源证据，再讨论为什么火。正式对标视频的可见点赞数必须大于等于 3,000，但不可用这一绝对值代替相对表现判定。
3. 迁移传播机制，不搬运原句、事实、人物经历或独特资源。
4. 内容即使删除产品信息也必须值得看；产品只作为自然落点。
5. 任何数字、经历、客户案例和结果承诺都必须能追溯到来源。
6. 标题和开头必须在正文方向确定后制作。
7. 所有模块使用 SDT 自有规则，不依赖其他技能才能运行。

## 运行模式

- 单项任务：默认模式，只运行标题、开头、封面、检索、选题、诊断或归档中的一个。
- 完整生产：仅在用户明确要求时，从目标账号和研究范围开始，交付一套可发布内容。
- 选题研究：停在选题池与评分，不写正文。
- 单项生产：标题、封面、开头、逐字稿等已有上游材料时单独处理。
- 复盘沉淀：把发布数据与结论写回内容资产系统。

## 完整生产线（仅显式触发）

按以下闸门顺序执行。读 references/pipeline.md 获取每一阶段输入、输出和退回条件。

1. 使用 sdt-account 建立账号档案。
2. 使用 sdt-research 获取账号、笔记、标题、封面和可见指标。
3. 使用 sdt-benchmark 筛出垂直、邻近、跨域三类样本。
4. 使用 sdt-spread 提炼爆款的承重传播机制。
5. 使用 sdt-topic 生成候选、建立目标账号桥梁并评分。
6. 用户只要求选题研究时到此停止；明确要求成稿时继续使用 sdt-content。
7. 使用 sdt-xhs-title、sdt-cover 和 sdt-hook 制作包装。
8. 使用 sdt-script-flow、sdt-resonate、sdt-ai-check 依次质检；只修复对应问题，不偷换主题。
9. 需要公众号版本时使用 sdt-wechat-html 生成发布文件。
10. 使用 sdt-content-system 保存来源、版本、表现和复盘。

## 独立调用规则

- 用户可直接调用任意 sdt-*，无需先调用 sdt。
- 总入口只传递当前模块真正需要的上下文。
- 某模块发现根本问题属于另一模块时，先交付本步骤能确定的结论，再说明缺少什么；不要自行启动长链。
- 标题最低输入是一个主题或一段正文；开头最低输入是正文或完整内容结构；跨域选题最低输入是目标账号简档和一个来源样本。
- 完整流程中的中间产物使用统一字段，单项任务则允许轻量输出。

## 统一交付

完整生产至少交付：

- 目标账号与本次内容目的
- 来源证据表
- 原始爆款机制
- 迁移桥梁与风险
- 选题评分
- 最终标题、封面、开头、正文或逐字稿
- 三类质检结果与修改说明
- 待发布假设和发布后应回填的指标

使用 assets/production-brief.md 作为交付骨架。

## 停止条件

- 无法确认目标账号，停止生产并只索取账号链接或档案。
- 检索遇到验证码、登录过期、限流或空响应，停止自动重试并报告。
- 来源内容缺少可核对指标，标为“灵感样本”，不得标为“低粉爆款”。
- 迁移必须伪造目标人物经历或专业资格，淘汰选题。
- 数据或健康、法律、金融主张无法验证，删除精确结论或补充可靠来源。
